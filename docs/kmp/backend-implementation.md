# Native backend implementation status

Implemented in the existing Worker, without changing DNS/MX, deployment, production data or secrets:

- v1 API contract, DTO normalization and raw-JWT adapter compatibility.
- Fixed-expiry D1 native sessions, per-device revoke/list, password/ban/delete revocation triggers, login/search/sync/send resource rate limits. Legacy login adds a compatible KV account/IP throttle, with eventual-consistency limitation; native login uses atomic D1 counters.
- Existing mail/account models reused; server search scans authorized full subject/sender/recipient/body data with filters and keyset pages.
- Atomic D1 event triggers and initialization seed, signed user/epoch cursor, bounded cycle watermark, pagination, authoritative current-state/tombstone replay.
- Transactional operation ledger read/unread/star/delete/restore; ownership predicates checked inside mutation transaction, not only earlier reads.
- Durable send claims/fingerprints, Resend provider idempotency, CC/BCC forwarding and persistence, authorized reply threading, internal BCC isolation, atomic sent-message linkage and conservative uncertain outcome recovery. Native send quotas reserve atomically to avoid concurrent limit overspend; uncertain outcomes retain reservation and require manual reconciliation.
- Auth route prefix/test bypass removed; star ownership bug fixed; private owner-authorized KV/R2/S3 downloads and inline attachment bytes, sanitized filenames, resource limits, safe download headers; password reset length bug fixed; dual-format legacy/PBKDF2 password verification and stronger new/reset hashes; sensitive ORM parameter/domain logging disabled.
- Native inline image DTOs normalize authorized CID and local object URLs (including percent-encoded Unicode keys) to numeric attachment references. Inline send budgets use actual downloaded object bytes, so stale size metadata cannot bypass the aggregate attachment limit. JWT expiry rejects explicitly zero, null or nonnumeric values while preserving legacy tokens with no expiry claim.

Validation is performed by `npm test` against isolated Cloudflare Workers D1/KV/R2 and Resend test doubles in `test/app-v1.spec.js`. Actual counts/results are recorded by QA in implementation-report; source availability is not evidence of successful tests. Worker deployment/migration and real external delivery remain operator release gates.

## HTTP integration fixture and rerun (2026-10-19)

Added `mail-worker/test/http-fixture.mjs`, started with `npm run test:fixture`. It bundles and runs the actual Worker on `127.0.0.1:8789` using Wrangler-pinned Miniflare/esbuild, ephemeral real D1/KV/R2, a schema shared with normal tests, and official migration parsing that preserves triggers. No deployment configuration or remote credentials are loaded; no Resend keys are provided, and an outbound service blocks external Worker network calls. See `mail-worker/test/HTTP-FIXTURE.md` for the synthetic account contract and lifecycle. The fixture supports native CIO integration tests without replacing API behavior with a fake HTTP server.

Final backend suite after the outgoing Message-ID fix: **35 tests in 3 files passed**, exit 0, at 2026-10-19 14:21 UTC (Vitest duration 23.92 seconds). Tests now additionally prove exactly-once URL key decoding, rejection of CRLF Message-ID before provider invocation, and rejection of private inline objects once every owned live parent is deleted. The initial deleted-parent fixture only deleted the original mail; the newly sent copy legitimately retained another owner association to the same content-addressed object. The corrected test deletes all owned parents before asserting denial; authorization behavior was correct. `git diff --check` passed.

Fixed a real threading defect: outgoing Message-ID is generated before provider submission, included in the Resend headers, and persisted unchanged in sent/internal copies. Reply headers retain that same original identity. The provider test double asserts the wire header equals the stored D1 value; actual Resend handling of that header remains a staging-delivery gate.

Also executed a real HTTP end-to-end flow against a separate isolated fixture on port 8790: login as both synthetic users, initial sync, mark read, internal send with attachment, replay the same operation without duplicate delivery, recipient server search, authorized attachment download, logout, then verify revoked credentials return HTTP 401. This passed. The first ad-hoc HTTP script stopped on an envelope-access assertion; the subsequent explicit-status version completed the whole flow successfully. Main port 8789 was restarted from final source for the native integration run. No production migration, deployment, external delivery or real user data was involved.

The native HTTP run exposed another real server defect: searching the full `Native HTTP E2E <UUID>` subject returned HTTP 500, while shorter prefixes worked. Reproduced independently with and without the trailing query ampersand. D1's LIKE pattern-byte limit was incompatible with the advertised 200-character query allowance. Search now uses `instr(lower(COALESCE(column,'')),lower(?))` across the same authorized fields, retaining case-insensitive ASCII literal substring behavior without wildcard interpretation. Added long subject, 200-character, Unicode, literal percent/underscore and trailing-ampersand regressions. Actual HTTP checks against the restarted Worker confirmed these queries return HTTP 200.

Rate-limit responses now include numeric `Retry-After` seconds until the current bucket resets, enabling bounded client retries during large incremental syncs. The existing login throttle test asserts that header is positive and bounded by its 300-second window. Final suite after both fixes: **36 tests across 3 files passed**, exit 0, 2026-10-19 14:26 UTC, Vitest duration 35.23 seconds. `git diff --check` passed. The isolated 8789 fixture was restarted with these final changes for native integration validation.

Limitations: D1 ledger retains all events/actions/send records until a reviewed retention/reset protocol; native message query uses indexed owner/folder keysets plus literal substring body search rather than optional FTS. Provider interruption before persistence can yield uncertain send; it is deliberately not auto-resubmitted. Private attachment enforcement cannot override a public bucket/custom-domain configuration. Legacy no-exp sliding JWT sessions remain accepted as required for transition; native session lifecycle is strong but does not force all Web users to reauthenticate. Existing webhook signature/URL-secret initializer/Telegram capability routes need operator-reviewed follow-up beyond native paths. Polling/background capability and encrypted local storage belong to KMP platform code.
